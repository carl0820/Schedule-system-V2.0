# 多机器人死锁检测与解决验证文档

## 概述

本文档说明系统在多机器人场景（4-8台机器人）下的死锁检测与解决机制，以及如何确保所有任务最终完成。

## 多机器人场景支持

### 1. 死锁检测支持

系统支持检测以下类型的多机器人死锁：

- **窄道死锁（Narrow Passage）**：多台机器人在窄道中相互阻塞
- **循环等待（Circular Wait）**：多台机器人形成循环等待链
- **相互阻塞（Mutual Blocking）**：多台机器人相互阻塞路径
- **资源竞争（Resource Contention）**：单个机器人卡住
- **活锁（Livelock）**：多台机器人反复移动但无法前进
- **饥饿（Starvation）**：任务长时间未分配

### 2. 死锁解决策略

根据机器人数量，系统采用不同的解决策略：

#### 2-3台机器人
- 让1台低优先级机器人后退或移动到等待点

#### 4-5台机器人
- 让一半（2-3台）低优先级机器人后退或移动到等待点
- 确保至少让2台机器人避让

#### 6台或更多机器人
- 让1/3的低优先级机器人后退或移动到等待点
- 确保至少让2台机器人避让
- 例如：6台机器人让2台避让，8台机器人让3台避让

### 3. 任务恢复机制

#### 3.1 任务记录

当机器人因死锁解除而移动时，系统会记录：
- 任务ID
- 原始action_id
- 等待点位置
- 开始时间
- 是否立即恢复（对于相互阻塞场景）

#### 3.2 任务恢复触发条件

任务会在以下情况下恢复：

1. **到达等待点**：机器人到达等待点（距离 < 0.5米）
2. **超时恢复**：如果30秒内未到达等待点，强制恢复
3. **立即恢复**：对于相互阻塞场景，后退后立即恢复任务

#### 3.3 任务恢复流程

1. 检查机器人是否到达等待点或超时
2. 重新发送move_to指令到原目标位置
3. 更新任务状态为EXECUTING
4. 设置新的action_id
5. 持久化任务状态

### 4. 多机器人场景处理流程

#### 场景1：窄道死锁（4-8台机器人）

1. **检测**：系统检测到多台机器人在窄道中相互阻塞
2. **选择避让机器人**：
   - 4-5台：选择2-3台低优先级机器人
   - 6台以上：选择1/3的低优先级机器人
3. **移动到等待点**：避让机器人移动到系统计算的等待点
4. **记录任务**：记录每个避让机器人的任务信息
5. **恢复任务**：当机器人到达等待点后，自动恢复任务执行
6. **验证完成**：系统持续监控，确保所有任务最终完成

#### 场景2：循环等待死锁（4-8台机器人）

1. **检测**：系统检测到多台机器人形成循环等待链
2. **选择避让机器人**：根据机器人数量选择1/3到1/2的低优先级机器人
3. **后退避让**：避让机器人后退一定距离
4. **记录任务**：记录每个避让机器人的任务信息
5. **立即恢复**：对于相互阻塞，后退后立即恢复任务
6. **验证完成**：系统持续监控，确保所有任务最终完成

#### 场景3：相互阻塞死锁（4-8台机器人）

1. **检测**：系统检测到多台机器人相互阻塞路径
2. **优先处理**：
   - 优先让没有任务的机器人避让
   - 如果所有机器人都有任务，按优先级排序
3. **后退避让**：避让机器人后退一定距离
4. **立即恢复**：后退后立即恢复任务（不需要等待点）
5. **验证完成**：系统持续监控，确保所有任务最终完成

### 5. 任务完成保证机制

#### 5.1 任务状态监控

系统在每次任务更新循环中：
1. 检查所有执行中的任务状态
2. 检查是否有机器人需要恢复任务
3. 更新任务状态（COMPLETED、FAILED、CANCELLED）

#### 5.2 超时保护

- **等待点超时**：如果30秒内未到达等待点，强制恢复任务
- **任务执行超时**：如果任务执行时间超过30秒且action_id失效，触发死锁检测

#### 5.3 任务恢复验证

系统通过以下方式验证任务恢复：
- 记录恢复日志（`[UNLOCK VERIFY]`标签）
- 检查任务状态是否更新为EXECUTING
- 验证新的action_id是否有效
- 监控任务最终是否完成

### 6. 日志验证

#### 6.1 死锁检测日志

查看 `logs/deadlock.log`，查找以下标签：
- `[DETECT]`：死锁检测开始和结果
- `[UNLOCK]`：死锁解除操作
- `[UNLOCK VERIFY]`：任务恢复验证
- `[RESOLVE]`：死锁解决策略

#### 6.2 任务恢复日志

查看 `logs/app.log`，查找以下信息：
- "Resuming task"：任务恢复
- "Task resumed successfully"：任务恢复成功
- "reached waiting point"：到达等待点

### 7. 验证步骤

#### 步骤1：创建多机器人任务

同时为4-8台机器人创建任务，确保它们在同一个区域相遇。

#### 步骤2：观察死锁检测

查看 `logs/deadlock.log`，确认：
- 系统检测到死锁（`[DETECT]`标签）
- 死锁类型正确识别
- 选择了正确数量的避让机器人

#### 步骤3：观察死锁解决

查看日志，确认：
- 避让机器人开始移动（`[UNLOCK]`标签）
- 任务被正确记录
- 避让机器人到达等待点或后退完成

#### 步骤4：观察任务恢复

查看日志，确认：
- 任务被恢复（`[UNLOCK VERIFY]`标签）
- 新的action_id被设置
- 任务状态更新为EXECUTING

#### 步骤5：验证任务完成

查看任务状态，确认：
- 所有任务最终完成（COMPLETED）
- 没有任务被卡住或丢失
- 所有机器人都能继续执行后续任务

### 8. 常见问题排查

#### 问题1：部分机器人任务未恢复

**原因**：
- 机器人未到达等待点
- 超时机制未触发

**解决**：
- 检查日志中的超时信息
- 确认机器人是否真的到达了等待点
- 检查任务状态是否正确

#### 问题2：死锁解除后任务被取消

**原因**：
- 任务恢复时action_id失效
- 机器人状态异常

**解决**：
- 检查任务恢复逻辑
- 确认机器人状态正常
- 查看任务恢复日志

#### 问题3：多台机器人同时避让失败

**原因**：
- 等待点计算失败
- 机器人移动失败

**解决**：
- 检查等待点计算逻辑
- 确认机器人是否能够移动到等待点
- 查看错误日志

### 9. 性能优化建议

1. **并发处理**：系统支持多台机器人同时进行死锁解除
2. **优先级策略**：根据任务优先级选择避让机器人
3. **超时保护**：设置合理的超时时间，避免任务长时间卡住
4. **日志记录**：详细记录死锁检测和解决过程，便于排查问题

### 10. 总结

系统已经完整支持多机器人场景（4-8台机器人）的死锁检测与解决：

✅ **检测能力**：能够检测各种类型的多机器人死锁
✅ **解决策略**：根据机器人数量动态调整避让策略
✅ **任务恢复**：确保所有任务在死锁解除后能够恢复
✅ **完成保证**：通过超时保护和状态监控，确保任务最终完成
✅ **日志记录**：详细记录整个过程，便于验证和排查

系统设计确保了在多机器人场景下，即使发生死锁，所有任务最终都能完成。
