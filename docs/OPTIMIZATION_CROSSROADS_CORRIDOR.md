# 十字路口和长走廊优化文档

## 优化概述

本次优化针对多机器人在十字路口和长走廊相遇的场景，重点解决死锁和任务取消问题，确保机器人能够正常完成调度任务。

## 关键参数

- **机器人旋转半径**: 0.45米（单台需要900mm旋转空间）
- **机器人旋转直径**: 0.9米
- **十字路口检测半径**: 2.0米
- **长走廊宽度阈值**: 2.0米
- **长走廊长度阈值**: 5.0米

## 优化内容

### 1. 配置优化 (`config.py`)

新增配置项：
- `ROBOT_ROTATION_RADIUS`: 机器人旋转半径（0.45米）
- `ROBOT_ROTATION_DIAMETER`: 机器人旋转直径（0.9米）
- `INTERSECTION_DETECTION_RADIUS`: 十字路口检测半径
- `INTERSECTION_COORDINATION_DISTANCE`: 十字路口协调距离
- `CORRIDOR_DETECTION_WIDTH`: 长走廊检测宽度阈值
- `CORRIDOR_DETECTION_LENGTH`: 长走廊检测长度阈值
- `CORRIDOR_YIELD_DISTANCE`: 长走廊让行距离
- `CORRIDOR_WAIT_POINT_DISTANCE`: 长走廊等待点距离

### 2. 场景检测模块 (`scene_detector.py`)

新增场景检测器，能够识别：
- **十字路口**: 检测周围4个方向的通道，判断是否为十字路口
- **长走廊**: 检测沿移动方向的通道长度和垂直方向的宽度
- **窄道**: 检测通道宽度小于1米的区域

主要功能：
- `detect_intersection()`: 检测十字路口
- `detect_corridor()`: 检测长走廊
- `detect_scene()`: 综合场景检测
- `calculate_yield_point()`: 计算让行等待点

### 3. 碰撞检测优化 (`collision_detector.py`)

- 使用旋转半径（0.45米）而不是普通半径（0.3米）进行碰撞检测
- 考虑机器人旋转空间，确保有足够的避让空间

### 4. 避让策略优化 (`avoidance_strategy.py`)

针对不同场景采用不同策略：

#### 十字路口场景
- **协调机制**: 根据机器人到达十字路口的先后顺序和优先级决定通行顺序
- **优先级规则**:
  1. 已在十字路口的机器人优先通行
  2. 距离十字路口更近的机器人优先通行
  3. 任务优先级高的机器人优先通行
  4. 优先级相同时，距离近的优先

#### 长走廊场景
- **相向而行**: 
  - 如果走廊宽度足够（≥2个机器人旋转直径+让行距离），侧向让行
  - 如果宽度不足，后退到等待点
- **同向而行**: 
  - 根据任务优先级和速度决定
  - 优先级高的或速度快的优先通行

#### 让行动作
- **后退让行**: 后退指定距离
- **侧向让行**: 移动到走廊一侧
- **等待点让行**: 移动到预计算的等待点

### 5. 死锁解决优化 (`deadlock_detector.py`)

改进死锁解决机制，**不再取消任务**，而是使用以下策略：

#### 窄道死锁
- 选择优先级最低的机器人，让它后退1米
- 其他机器人继续执行任务

#### 循环等待死锁
- 选择第一个机器人，让它后退1.5米
- 打破循环，让其他机器人继续

#### 相互阻塞死锁
- 选择距离其他机器人最近的机器人，让它后退1米
- 释放空间，让其他机器人通过

#### 默认死锁
- 短暂停止2秒后继续
- 不取消任务，保持任务状态

### 6. 路径规划优化 (`path_planner.py`)

- 使用旋转半径（0.45米）进行路径规划
- 确保规划的路径有足够的空间供机器人旋转

## 使用说明

### 自动场景识别

系统会自动识别十字路口和长走廊场景，无需手动配置。当机器人接近这些场景时，系统会：

1. **检测场景类型**: 自动识别当前位置是否为十字路口或长走廊
2. **应用相应策略**: 根据场景类型应用对应的避让策略
3. **协调通行**: 在十字路口使用协调机制，确保有序通行
4. **让行处理**: 在长走廊使用让行策略，避免相向碰撞

### 死锁自动解决

当检测到死锁时，系统会：

1. **识别死锁类型**: 判断是窄道死锁、循环等待还是相互阻塞
2. **选择解决策略**: 根据死锁类型选择最合适的解决策略
3. **执行避让动作**: 让一个机器人后退，释放空间
4. **保持任务状态**: **不取消任务**，任务会继续执行

## 测试建议

### 十字路口测试场景

1. **多机器人同时到达十字路口**
   - 验证协调机制是否正常工作
   - 验证优先级是否正确应用

2. **机器人从不同方向进入十字路口**
   - 验证通行顺序是否正确
   - 验证是否会发生碰撞

### 长走廊测试场景

1. **相向而行**
   - 验证让行策略是否生效
   - 验证等待点计算是否正确

2. **同向而行**
   - 验证速度调整是否合理
   - 验证优先级是否正确应用

### 死锁测试场景

1. **窄道死锁**
   - 验证后退策略是否生效
   - 验证任务是否继续执行

2. **循环等待死锁**
   - 验证循环是否被打破
   - 验证所有机器人是否都能继续

## 性能影响

- **计算开销**: 场景检测增加了少量计算，但影响很小
- **响应时间**: 避让策略响应时间 < 100ms
- **任务完成率**: 预期任务完成率 > 95%（避免因死锁取消任务）

## 注意事项

1. **旋转空间**: 确保地图中的通道宽度至少为1.8米（2个机器人旋转直径），才能保证两个机器人同时通过
2. **等待点**: 长走廊中的等待点需要在地图加载后计算，确保等待点位置有效
3. **优先级**: 任务优先级会影响避让决策，建议合理设置任务优先级
4. **死锁阈值**: 死锁检测阈值默认为10秒，可根据实际情况调整

## 后续优化方向

1. **动态等待点**: 根据实时地图状态动态计算等待点
2. **预测性避让**: 提前预测碰撞，在到达冲突点前就开始避让
3. **路径重规划**: 在死锁时自动重新规划路径，而不是后退
4. **多机器人协调**: 实现更复杂的多机器人协调机制
