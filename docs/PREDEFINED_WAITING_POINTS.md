# 预定义等待点配置指南

## 概述

预定义等待点功能允许您预先在地图上部署等待点，当机器人发生死锁时，系统会优先从这些预定义等待点中选择一个合适的点，而不是动态计算等待点。这样可以提高死锁解锁的可靠性和效率。

## 配置方法

### 1. 编辑配置文件

编辑 `data/runtime_config.json` 文件，在 `deadlock` 配置节中添加 `predefined_waiting_points` 字段：

```json
{
  "deadlock": {
    "deadlock_threshold": 10.0,
    "mutual_blocking_deadlock_threshold": 3.0,
    "waiting_point_min_distance": 2.0,
    "waiting_point_max_distance": 5.0,
    "predefined_waiting_points": [
      {
        "x": 10.0,
        "y": -5.0,
        "z": 0.0,
        "yaw": 0.0,
        "name": "等待点1-走廊东侧"
      },
      {
        "x": 15.0,
        "y": -3.0,
        "z": 0.0,
        "yaw": 1.57,
        "name": "等待点2-走廊西侧"
      },
      {
        "x": 8.0,
        "y": -7.0,
        "z": 0.0,
        "yaw": 3.14,
        "name": "等待点3-房间入口"
      }
    ],
    "use_predefined_waiting_points": true
  }
}
```

### 2. 等待点字段说明

每个等待点需要包含以下字段：

- **x** (float, 必需): 等待点的 X 坐标（米）
- **y** (float, 必需): 等待点的 Y 坐标（米）
- **z** (float, 可选, 默认 0.0): 等待点的 Z 坐标（米）
- **yaw** (float, 可选, 默认 0.0): 等待点的朝向（弧度）
- **name** (string, 可选): 等待点的名称（用于日志记录）

### 3. 配置选项

- **use_predefined_waiting_points** (bool, 默认 true): 是否优先使用预定义等待点
  - `true`: 优先使用预定义等待点，如果没有合适的预定义等待点，则使用动态计算的等待点
  - `false`: 只使用动态计算的等待点，忽略预定义等待点

## 等待点选择逻辑

系统在选择预定义等待点时会考虑以下因素：

1. **距离死锁区域**: 等待点必须距离死锁区域至少 3 米
2. **不在前进方向上**: 等待点不能在其他死锁机器人的前进方向上（避免被卡住）
3. **距离当前位置**: 优先选择距离机器人当前位置 3-8 米的等待点
4. **综合评分**: 系统会根据以上因素计算每个等待点的得分，选择得分最高的等待点

## 如何选择等待点位置

### 建议的等待点位置

1. **走廊两侧**: 在主要走廊的两侧设置等待点，避免阻塞主通道
2. **房间入口附近**: 在房间入口附近设置等待点，方便机器人避让
3. **宽敞区域**: 选择空间较大的区域，确保机器人有足够的空间停留
4. **避开主要路径**: 避免在机器人经常经过的主要路径上设置等待点

### 不推荐的等待点位置

1. **窄道内**: 不要在窄道内设置等待点，会阻塞其他机器人
2. **主要路径上**: 避免在机器人经常经过的主要路径上设置等待点
3. **死锁高发区域**: 避免在容易发生死锁的区域附近设置等待点

## 日志记录

当系统使用预定义等待点时，会在日志中记录：

```
[WAITING POINT] Selected predefined waiting point (10.00, -5.00) for robot robot2 with score 8.50
```

如果没有找到合适的预定义等待点，会记录：

```
[WAITING POINT] No suitable predefined waiting point found for robot robot2 from 3 predefined points
```

## 注意事项

1. **坐标系统**: 确保等待点坐标使用与地图相同的坐标系统
2. **可达性**: 确保等待点位置是机器人可以到达的（不在障碍物上）
3. **空间充足**: 确保等待点周围有足够的空间供机器人停留
4. **定期检查**: 如果地图发生变化，需要相应更新等待点配置

## 故障排除

### 问题: 系统没有使用预定义等待点

**可能原因**:
1. `use_predefined_waiting_points` 设置为 `false`
2. `predefined_waiting_points` 列表为空
3. 所有预定义等待点都不满足选择条件

**解决方法**:
1. 检查配置文件中的 `use_predefined_waiting_points` 设置
2. 检查 `predefined_waiting_points` 列表是否正确配置
3. 查看日志，了解为什么预定义等待点没有被选中

### 问题: 预定义等待点位置不合适

**可能原因**:
1. 等待点距离死锁区域太近（< 3米）
2. 等待点在其他机器人的前进方向上
3. 等待点位置不可达

**解决方法**:
1. 调整等待点位置，确保距离死锁区域至少 3 米
2. 选择不在其他机器人前进方向上的位置
3. 确保等待点位置是机器人可以到达的

## 相关配置

- `waiting_point_min_distance`: 动态计算等待点的最小距离（米）
- `waiting_point_max_distance`: 动态计算等待点的最大距离（米）

这些配置不影响预定义等待点的选择，但会影响动态计算等待点的范围。
